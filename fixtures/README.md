# Fixtures — synthetic data disclosure

Every file in this directory is **synthetic**. None of it is a real
postfiatd node log and none of it comes from a live network. The fixtures
exist so the harness and detectors can be run and reproduced by anyone
without operating a validator.

## What is real and what is synthetic

| Element | Status | Source |
|---|---|---|
| JLOG message texts (`CNF Val`, `CNF buildLCL`, `Consensus detects as stalled with ...`, `Remaining free disk space is less than 512MB`, `ValidatorKeys not set`, `Closed`, `<peer> failed: ...`, `Ledger ... missing recent ancestor hashes`, `RCLValidations: Recording vote with ...`, `Consensus engine started`, `Validator identity:`, `Need consensus ledger`) | **Verbatim from pinned source** | postfiatd commit `0085a1ff885d6a446369cf73a4430f75af22be55`; see `docs/source-inventory.md` for file, line and blob SHA of each message |
| Timestamps, ledger hashes, peer addresses, node keys, account IDs, cookies, close times, sign times | **Synthetic** | Generated by `scripts/generate_fixtures.py` from fixed parameters |
| Ledger sequences 900000–900119 and the 4 s close interval | **Model assumptions** | Documented in `docs/methodology.md`; not measured network facts |
| Peer addresses `203.0.113.1–12:2559` | **Synthetic** | TEST-NET-3 documentation range (RFC 5737); no real peer |
| Node key `n9SyntheticValidatorIdentity...` / account `rSyntheticValidatorAccount...` | **Synthetic placeholders** | Clearly fake strings; not a real key |

## Log-line format

Each line is:

```
2026-11-20T00:00:04.000Z [RCLConsensus] CNF Val <64-hex ledger hash>
```

The timestamp is ISO-8601 UTC with millisecond precision and the
bracket tag is the journal name used by the JLOG call site
(`RCLConsensus`, `Validations`, `Peer`, `Node`). This is the pack's own
synthetic log format: it is **not** claimed to be byte-identical to the
beast journal sink's output. The detectors key on the message texts,
which are verbatim, not on the timestamp format.

## Fixture pairs

Each fixture is a log plus a ledger-state JSON with the same base name:

| Fixture | Ledgers | What it models |
|---|---|---|
| `baseline-healthy` | 120, all validated | Healthy validator; control case |
| `connectivity-loss` | 120, 25 missed (900050–900074) | All 12 peers disconnect at once; 100 s partition |
| `clock-skew` | 120, all issued locally; 20 with signTime +400 s (900040–900059) | Local clock jumps +400 s; validations stale to the network |
| `resource-exhaustion` | 120, 30 missed (900060–900089) | Fatal low-disk line, then 120 s halted |
| `config-error` | 120, 0 validated | No validator keys configured; keys warnings on every ledger |
| `consensus-stall` | 120, 20 missed (900030–900039, 900070–900079) | Two engine stall events |

The ledger-state JSON is the "ledger state" the harness reads: per
ledger `seq`, `hash`, `close_time`, `sign_time`, `validated`. The
parser cross-checks the JSON `validated` flags against the log's
`CNF Val` lines and reports any disagreement instead of hiding it
(see `outputs/parse-*.log`, "ledger-state JSON agrees with log").

## Regeneration

`bash scripts/run_all.sh` step 1 regenerates these files with
`scripts/generate_fixtures.py`. The generator is deterministic: no
wall-clock time, no randomness. Re-running produces byte-identical
files (SHA-256 printed by the generator and recorded in
`run-manifest.json`).
